# CLAUDE.md — «Индекс счастья» (MVP)

## Что это за проект

Веб-сервис для российского рынка: короткий бесплатный тест (около 5 минут, 28 вопросов) показывает человеку
личный «индекс счастья», тип личности (8 своих архетипов по трём осям) и три главные «утечки счастья».
Полный персональный разбор продаётся за 490 / 690 / 990 ₽ (A/B-тест цены).

**MVP — это эксперимент, а не продукт.** Его единственная задача — измерить четыре метрики и сравнить
их с порогами:

| Метрика | Идём дальше | Стоп |
|---|---|---|
| Старт → прошёл тест | ≥ 60% | < 45% |
| Прошёл → поделился | ≥ 8% | < 4% |
| Прошёл → купил отчёт | ≥ 2,5% | < 1,2% |
| Купил → клик по фейковой подписке | ≥ 5% | — |

Любое решение, которое мешает точно измерить эти метрики, — неправильное решение.

## Какая версия основная

- **Основная версия — `web/`** (Next.js). Вся новая работа идёт там.
- **Python-версия** (`app/`, `migrations/`, `config/`, `docs/`, `deploy/` в корне) — **заморожена как референс**
  на `main`. Не меняй её. Читать можно: там утверждённые тексты, ТЗ (`docs/SPEC.md`) и юридические
  требования (`docs/LEGAL.md`). С её `config/` сравнивает тексты `npm run texts:review`.

## Где что лежит (`web/`)

- `web/README.md` — запуск, флоу на моках, структура. `web/LAUNCH.md` — с моков на прод.
- `web/DECISIONS.md` — принятые решения. `web/TODO.md` — что осталось.
- `web/config/questionnaire.yaml` — вопросы, шкала, веса, оси, типы, утечки, пороги, данные ВЦИОМ.
  Единственный источник правды по тесту.
- `web/config/app.yaml` — цены A/B, пейволл, фейковая дверь, порог перцентиля, пороги метрик, отчёт.
- `web/prompts/report.md` — промпт внешней LLM.
- `web/docs/TEXTS_REVIEW.md` — все тексты для вычитки (генерируется).

## Стек (менять только с согласия владельца)

- Next.js 15 (App Router, SSR) + TypeScript, Tailwind 4. Без клиентского SPA: страницы рендерит сервер, нужен SEO.
- SQLite через Drizzle ORM (`@libsql/client`), миграции в `web/drizzle/`
- zod — валидация конфигов и ответа LLM
- `next/og` (satori) — карточка 1080×1920 и OG-картинки; pdfkit — PDF отчёта
- Платежи: интерфейс `PaymentProvider`, `mock` и ЮKassa (REST API). Только тестовый режим, пока владелец
  явно не скажет иначе.
- LLM: `mock` (шаблоны), `yandexgpt`, `openai` — переменная `LLM_PROVIDER`
- Vitest, Playwright, ESLint; Docker + docker-compose (+ Caddy для HTTPS); CI — `.github/workflows/ci.yml`

## Команды (из `web/`)

```bash
npm install && npm run setup && npm run dev   # миграции + 500 синтетических результатов + dev-сервер
npm run lint && npm run typecheck && npm test # ESLint, tsc, Vitest
npm run build                                 # production-сборка
npm run smoke                                 # HTTP-smoke всего пути без порта и браузера (после build)
npx playwright install chromium               # один раз
npm run test:e2e                              # Playwright (после build), порт — E2E_PORT, по умолчанию 3100
npm run screenshots                           # скриншоты экранов → docs/screenshots (после build)
npm run texts:review                          # пересобрать docs/TEXTS_REVIEW.md после правки текстов
npm run db:generate                           # новая миграция после правки lib/db/schema.ts
docker compose up -d --build                  # прод-запуск; с HTTPS: --profile https (DOMAIN в .env)
```

Без ключей всё работает на моках: оплата — страница `/pay/mock/{id}` с подписанным вебхуком, отчёт —
шаблоны, письма — лог с замаскированным адресом, Метрика выключена. `/admin` — basic auth по `ADMIN_PASSWORD`.

## Правила работы

1. **Задачи — от владельца, по одной.** В конце: lint, typecheck, unit, build и smoke зелёные (e2e — в CI),
   коротко отчитайся, что сделано и как проверить. Не начинай следующую задачу без подтверждения.
   Решения, принятые без владельца, записывай в `web/DECISIONS.md`.
2. **Подсчёт результатов — только из `web/config/questionnaire.yaml`** и только в `web/lib/scoring.ts`.
   Функции чистые (без БД и HTTP) и покрыты юнит-тестами на граничные значения.
3. **Тексты вопросов — только из `web/config/questionnaire.yaml`:** собственные утверждения проекта или
   пункты IPIP (общественное достояние). Лицензионные шкалы не используем; новые тексты не придумывай —
   их даёт или утверждает владелец (вычитка — `web/docs/TEXTS_REVIEW.md`). В маркетинге — «основан на модели
   Большой пятёрки», без «валидированный» и «научно доказанный».
4. **Весь пользовательский текст — на русском**, на «ты», тёплый и спокойный тон. Без обещаний «вылечить»,
   «изменить жизнь за 7 дней», без медицинских терминов в результатах.
5. **Слово «MBTI» и названия 16 типов Майерс-Бриггс нигде не используем** — это чужая торговая марка.
   Типы — только свои архетипы из `config/questionnaire.yaml`.
6. **Персональные данные — минимум.** Тест анонимный. Email появляется только при покупке или подписке на
   уведомление. Никаких ПДн в URL, логах и аналитике. В LLM уходят только баллы и ответы — без email и id.
7. **Политика и новости — вне продукта.** Ни в интерфейсе, ни в отчёте нет рассуждений о причинах падения
   индекса в стране.
8. **Секреты — только в `.env`**, `.env` в `.gitignore`. Шаблон — `web/.env.example`. CI работает на моках
   и секретов не требует.
9. **Каждое событие воронки пишется на сервер** (таблица `events`) в дополнение к Яндекс Метрике:
   метрики MVP считаются по серверным событиям, Метрика — вспомогательная.
10. **Синтетические результаты (`is_seed`)** участвуют только в перцентиле до порога
    `percentile.real_results_threshold` и никогда — в аналитике.

## Чего не делать в MVP

Мобильное приложение, аккаунты с паролем, настоящая подписка с рекуррентными платежами, консультации,
блог/SEO-библиотека, мультиязычность, клиентский SPA. Если задача требует чего-то из этого — остановись и спроси.
