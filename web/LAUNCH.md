# LAUNCH — с моков на прод

Порядок: юрлицо и юр. тексты → ключи (тестовые) → сервер, домен, HTTPS → проверка → боевые ключи → трафик.
Все ключи кладутся в `.env` на сервере (шаблон — `.env.example`) и никогда не коммитятся.

## 1. Юридические шаги (до приёма денег)

- [ ] **Статус.**
  - Самозанятость (НПД): самый простой вариант, но ЮKassa работает с самозанятыми с ограничениями. Проверь
    актуальные условия в разделе «Самозанятым» на yookassa.ru.
  - Для полноценной работы с чеками и рекламой обычно выбирают **ИП на УСН 6%**. Регистрация — через
    Госуслуги или «Мой налог» / ФНС.
- [ ] **Уведомление Роскомнадзора** о начале обработки персональных данных (сайт собирает email). Подаётся
  на pd.rkn.gov.ru до начала обработки, то есть до запуска.
- [ ] **Чеки 54-ФЗ.** При ИП подключи «Чеки от ЮKassa» или облачную кассу. Код ставки НДС в чеке задаётся
  в `YOOKASSA_VAT_CODE`, сверь его с бухгалтером.
- [ ] **Маркировка рекламы (ERID)** — до закупки рекламы у блогеров и в сетях. В рекламных кабинетах VK
  и Яндекса она встроена.

## 2. Юридические тексты

Шаблоны лежат в `lib/legal.ts` и отображаются на `/legal/offer`, `/legal/privacy`, `/legal/consent`. Заполни
с юристом все плейсхолдеры в квадратных скобках:

| Плейсхолдер | Где |
|---|---|
| `[ФИО ИП]`, `[ИНН]`, `[ОГРНИП]`, `[адрес]` | все три документа |
| `[email для обращений]` | все три документа |
| `[домен]`, `[дата]` | оферта, согласие |
| `[наименование платёжного провайдера]` | оферта, политика |
| `[наименование хостинга]`, `[наименование LLM-провайдера]`, `[срок]` | политика |
| `[14]`, `[10]` | сроки возврата и удаления — сверь с `pricing.refund_days` в `config/app.yaml` |

После правки убери жёлтую плашку «Шаблон документа» в `app/legal/[doc]/page.tsx`.

## 3. Ключи

### ЮKassa

1. Зарегистрируйся на yookassa.ru и создай **тестовый магазин**: в личном кабинете «Магазины» → «Добавить
   тестовый».
2. «Интеграция» → «Ключи API» → выпусти секретный ключ. Для тестового магазина он начинается с `test_`.
3. В `.env`:
   ```
   PAYMENT_PROVIDER=yookassa
   YOOKASSA_SHOP_ID=<shopId>
   YOOKASSA_SECRET_KEY=test_...
   ```
4. «Интеграция» → «HTTP-уведомления»: URL `https://<домен>/api/webhooks/payment`, события
   `payment.succeeded` и `payment.canceled`. Вебхуку код не доверяет: статус и сумма перепроверяются
   запросом к API ЮKassa.
5. Проведи тестовую оплату тестовой картой из документации ЮKassa. Убедись, что открылся отчёт, а в
   `/admin` заказ «оплачен».
6. После договора и боевого магазина замени `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` на боевые (`live_...`)
   и перезапусти.

### LLM для отчёта

Без ключа отчёт собирается из шаблонов (mock). Он персонализирован и проходит все проверки, поэтому можно
запускаться и так.

- **YandexGPT** (рекомендуется для РФ: данные остаются в России):
  1. Yandex Cloud → создай каталог и сервисный аккаунт с ролью `ai.languageModels.user`.
  2. Выпусти API-ключ.
  3. В `.env`: `LLM_PROVIDER=yandexgpt`, `YANDEXGPT_API_KEY`, `YANDEXGPT_FOLDER_ID` (id каталога),
     `YANDEXGPT_MODEL` (например `yandexgpt/latest`). Лучше закрепить конкретную версию модели, чтобы тексты
     не менялись без предупреждения.
- **OpenAI / совместимый шлюз:** `LLM_PROVIDER=openai`, `OPENAI_API_KEY`, при необходимости `OPENAI_BASE_URL`
  и `OPENAI_MODEL`. Внимание: это трансграничная передача данных. Ответы теста анонимны (без email и id),
  но юрист должен это одобрить и отразить в политике.
- Если модель вернула невалидный JSON, будет повтор (`report.max_attempts` в `config/app.yaml`), затем
  fallback на шаблоны. Доля fallback видна в событиях `report_view` (`props.fallback`).
- Проверь 3–5 реальных отчётов глазами: тон, отсутствие диагнозов и обещаний.

### Письма со ссылкой на отчёт

`MAIL_PROVIDER=smtp`, `SMTP_HOST`, `SMTP_PORT` (465 — SSL), `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM`.
Подойдут Яндекс 360 для домена, Unisender Go, Mail.ru для бизнеса. Настрой SPF и DKIM для домена, иначе
письма уйдут в спам.

### Яндекс Метрика

1. metrika.yandex.ru → «Добавить счётчик» → домен сайта. Вебвизор не нужен.
2. Номер счётчика — в `YM_COUNTER_ID`.
3. Метрика грузится только после того, как посетитель нажал «Принять» в cookie-баннере. Те же события
   уходят в неё как `reachGoal`.
4. Если нужны цели в интерфейсе Метрики, создай цели типа «JavaScript-событие» с идентификаторами:
   `test_complete`, `share_click`, `paywall_view`, `payment_success`, `subscription_click`.

Метрики MVP считаются по **серверным** событиям в `/admin`, а Метрика — вспомогательная.

### Прочее

- `ADMIN_PASSWORD` — длинный случайный пароль.
- `MOCK_WEBHOOK_SECRET` — любая строка. В проде мок не используется.
- `APP_URL=https://<домен>` — от него строятся ссылки в шеринге, письмах и `return_url`.

## 4. Деплой на российский хостинг

Подойдёт любой VPS с Docker: **Timeweb Cloud**, **Selectel** или **Yandex Cloud** (Compute Cloud).
Хватит 1 vCPU, 2 ГБ RAM и 20 ГБ диска, Ubuntu 24.04.

1. Создай VPS и запиши его публичный IP.
2. В DNS домена добавь **A-запись** `@` → IP. Для `www` — ещё одну A-запись или CNAME.
3. На сервере:
   ```bash
   curl -fsSL https://get.docker.com | sh
   git clone <репозиторий> happiness && cd happiness/web
   cp .env.example .env && nano .env      # APP_URL=https://<домен>, DOMAIN=<домен>, ключи, пароль
   docker compose --profile https up -d --build
   ```
   - Caddy сам выпустит сертификат Let's Encrypt для `DOMAIN` и будет его продлевать.
   - Порты 80 и 443 должны быть открыты в firewall или группе безопасности.
4. Проверка: `curl https://<домен>/api/health` → `{"ok":true}`. Пройди тест и оплату с телефона.
5. **Бэкап базы.** SQLite лежит в docker-томе `app-data`. Ежедневная копия (cron):
   ```bash
   docker compose exec -T app node -e "require('fs').copyFileSync('/data/app.db','/data/backup-'+new Date().toISOString().slice(0,10)+'.db')"
   ```
   Храни копии вне сервера: Object Storage в Yandex Cloud или S3 в Selectel и Timeweb.
6. **Обновление:** `git pull && docker compose --profile https up -d --build`. Миграции применяются при старте.

Без своего домена можно временно открыть `http://<IP>:3000`, но ЮKassa требует https для вебхуков.

## 5. Перед первым трафиком

- [ ] Проверь данные ВЦИОМ в `config/questionnaire.yaml` → `country` (доля счастливых, период, ссылка).
  Заголовок лендинга «падает» тоже должен соответствовать данным.
- [ ] Посмотри 3 новых утверждения `life_6`, `life_7`, `life_8` (см. DECISIONS.md) и при желании замени.
- [ ] Пройди тест сам со своего браузера и купи разбор в тестовом режиме.
  - Твои визиты попадут в метрики. Удали их перед стартом: `DELETE FROM events; DELETE FROM orders; …`
    через `sqlite3` в томе — или просто пересоздай том до запуска.
- [ ] `SEED_ON_START=true` оставь до 500 настоящих результатов. После порога перцентиль сам переключится на
  настоящие данные (`percentile.real_results_threshold` в `config/app.yaml`).

## 6. Первый трафик с UTM

Каждая ссылка в рекламе — со своими метками. Сохраняется первый визит посетителя:

```
https://<домен>/?utm_source=vk&utm_medium=cpc&utm_campaign=launch&utm_content=banner_a
https://<домен>/?utm_source=telegram&utm_medium=post&utm_campaign=launch&utm_content=channel_name
https://<домен>/?utm_source=yandex&utm_medium=cpc&utm_campaign=launch
```

- Ссылки шеринга сами получают `utm_source=telegram|vk|copy&utm_medium=share`. Вирусный трафик виден в
  `/admin` → «По источникам».
- Сколько нужно трафика: чтобы 95%-интервал конверсии в покупку не задевал второй порог, нужно примерно
  300 завершённых тестов, если конверсия около 1,2%, и около 560, если она около 2,5%. На каждый вариант цены — втрое больше, если сравнивать цены между собой. Смотри на
  95%-интервалы в карточках метрик: пока они пересекают оба порога, цвет ещё не вывод.
- **Решение по эксперименту** — по `/admin`. Зелёные метрики и красные метрики сравниваются с порогами из
  таблицы в README.
