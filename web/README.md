# Индекс счастья — MVP (Next.js)

B2C веб-тест для российского рынка по модели «бесплатный тест → платный отчёт». За 5 минут человек
получает личный индекс счастья (0–100), тип личности (8 типов по трём осям), три главные «утечки счастья»
и сравнение с долей счастливых в России. Полный персональный разбор с планом на 30 дней стоит
490 / 690 / 990 ₽ (A/B-тест). Ниже есть фейковая дверь подписки «Трекер счастья».

**MVP — это эксперимент.** Он меряет четыре метрики и сравнивает их с порогами. Метрики видны в `/admin`:

| Метрика | Цель | Стоп |
|---|---|---|
| Старт → завершил тест | ≥ 60% | < 45% |
| Завершил → поделился | ≥ 8% | < 4% |
| Завершил → купил отчёт | ≥ 2,5% | < 1,2% |
| Купил → кликнул «подписка» | ≥ 5% | — |

## Запуск за 2 минуты

Нужен Node.js 20.9+ (проверено на 22 и 25).

```bash
cd web
npm install && npm run setup && npm run dev
```

Открой http://localhost:3000. Ключи не нужны: оплата, LLM, письма и аналитика работают на моках.
`npm run setup` создаёт SQLite-базу `data/app.db`, применяет миграции и кладёт 500 синтетических
результатов для перцентиля. Синтетика помечена `is_seed` и в аналитику не входит.

Чтобы войти в админку, скопируй `.env.example` в `.env` и задай `ADMIN_PASSWORD`. Без пароля `/admin`
выключена. В basic auth логин любой.

## Как пройти весь флоу на моках

1. **Лендинг** `/` → «Пройти тест».
2. **Тест** `/test` — 28 вопросов, по одному на экран.
   - Клавиши 1–5 выбирают ответ, ← возвращает назад.
   - Перезагрузи страницу посреди теста: продолжишь с того же места.
3. **Результат** `/result/<id>` — индекс со шкалой, перцентиль, тип, утечки, строка про Россию.
   - Шеринг: Telegram, VK, ссылка, PNG 1080×1920.
   - Пейволл и «Трекер счастья».
4. **Цена.** Чтобы увидеть другую цену, открой `/result/<id>?price=490`, `?price=690` или `?price=990`. Вариант
   закрепится в cookie.
5. **Оплата.** «Получить разбор» → email и согласие с офертой → **тестовая касса** `/pay/mock/...`.
   - «Оплатить успешно» шлёт подписанный вебхук на `/api/webhooks/payment`.
   - «Отказ» помечает заказ неоплаченным.
6. **Отчёт** `/report/<orderId>` — разбор на 1500+ слов и кнопка «Скачать PDF». Письмо со ссылкой в mock-режиме
   не уходит: в консоль сервера пишется строка `[mail:mock] … → b***@example.ru`.
7. **Админка** `/admin`:
   - 4 метрики с цветом и доверительным интервалом;
   - воронка;
   - разбивка по цене и `utm_source`;
   - доходимость по вопросам;
   - заказы и email;
   - выгрузка CSV.
   UTM попадают в разбивку, если первый визит был, например, на `/?utm_source=test`.

## Проверки

```bash
npm run lint        # ESLint
npm run typecheck   # tsc --noEmit
npm test            # Vitest: подсчёт, A/B, платёжный мок-флоу, отчёт, метрики админки
npm run build       # production-сборка
npm run test:e2e    # Playwright: лендинг → тест → результат → оплата (мок) → отчёт → админка
npm run smoke       # HTTP-smoke всего пути без порта и браузера (после npm run build)
npm run screenshots # скриншоты всех экранов → docs/screenshots (после npm run build)
npm run texts:review # docs/TEXTS_REVIEW.md — все тексты на вычитку с пометками «новый/изменён»
```

В GitHub Actions (`.github/workflows/ci.yml`) на каждый push и PR это идёт автоматически, на моках и без
секретов: проверки и smoke, e2e со скриншотами (артефакты `screenshots` и `playwright-report`), сборка
Docker-образа и запуск контейнера с проверкой главной страницы. Порт, хост и адрес сервера для e2e
задаются через `E2E_PORT`, `E2E_HOST`, `E2E_BASE_URL` (см. `playwright.config.ts`).

Перед первым e2e поставь браузер: `npx playwright install chromium`. E2E поднимает production-сборку на
порту 3100 с отдельной базой `data/e2e.db`.

## Структура

```
web/
  app/                    страницы и API (App Router)
    page.tsx              лендинг
    test/                 тест
    result/[id]/          бесплатный результат, шеринг, пейволл, фейковая дверь
    pay/mock/[paymentId]/ тестовая касса
    order/[id]/           возврат из кассы, ожидание вебхука
    report/[id]/          полный отчёт (только после оплаты)
    legal/[doc]/          оферта, политика ПДн, согласие (шаблоны)
    admin/                дашборд эксперимента
    api/                  test/start, answers, test/complete, events, checkout, webhooks/payment,
                          pay/mock, leads, card, og, report/{status,pdf}, admin/export, health
  components/             клиентские компоненты: TestRunner, IndexGauge, Paywall, ShareBlock, FakeDoor, …
  config/
    questionnaire.yaml    вопросы, шкала, веса, оси, типы, утечки, пороги, данные ВЦИОМ
    app.yaml              цены A/B, тексты пейволла, фейковая дверь, пороги метрик, настройки отчёта
  prompts/report.md       промпт для внешней LLM
  lib/
    scoring.ts            подсчёт — чистые функции
    config.ts             загрузка и проверка YAML (zod)
    ab.ts                 назначение варианта цены
    test-flow.ts          старт, ответы (upsert), завершение
    payments/             PaymentProvider: mock, yookassa, сервис заказов
    report/               схема отчёта (zod), вход для LLM, mock-генератор, провайдеры, PDF
    events.ts             реестр событий и белый список свойств
    admin-metrics.ts      агрегация воронки и метрик
    db/                   схема Drizzle и клиент SQLite (libsql)
  drizzle/                SQL-миграции
  scripts/                migrate.ts, seed.ts
  middleware.ts           cookie посетителя, A/B-цена, first-touch UTM, basic auth админки
  tests/unit, tests/e2e, tests/smoke
  Dockerfile, docker-compose.yml, Caddyfile
```

## Что где менять без кода

- **Вопросы, веса, типы, тексты утечек, порог типа, данные ВЦИОМ** — `config/questionnaire.yaml`. Схема
  проверяется при старте, и ошибка в YAML не даст приложению подняться.
- **Цены A/B, пейволл, «Трекер счастья», пороги метрик** — `config/app.yaml`.
- **Промпт отчёта** — `prompts/report.md`.

После правки перезапусти сервер (`npm run dev` или `docker compose restart app`).
