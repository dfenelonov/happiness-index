# Ручная проверка

Два прохода. Первый — по галерее `/dev/qa`, около 15 минут: все экраны без прохождения теста. Второй — живой
путь, около 10 минут: как у настоящего человека. Отмечай `[x]`. Что нашёл — пиши прямо под пунктом.

**Подготовка.**
- Локально: `cd web && npm run setup && npm run dev` → http://localhost:3000/dev/qa.
- На сервере: сначала войди в `https://<домен>/admin` (логин любой, пароль `ADMIN_PASSWORD`), затем открой
  ссылку «QA-галерея» в шапке админки. Без пароля `/dev/*` в production отвечает 404.
- Нажми **«Создать демо-данные»**. Браузер станет владельцем демо-результатов; в метрики они не попадают.
- В конце нажми «Удалить демо-данные и выйти из QA-режима».

## Часть 1. Галерея `/dev/qa`

### §1. Общее
- [ ] **Лендинг.** Заголовок, подзаголовок «5 минут, без регистрации», кнопка «Пройти тест». Блоки «Как это
  работает» (3 шага), «Пример результата», FAQ (5 вопросов раскрываются), нижняя кнопка, футер.
- [ ] **«Лендинг с cookie-баннером».**
  - Баннер виден в углу.
  - После «Только необходимые» и обновления страницы баннер больше не появляется.
  - То же с «Принять».
- [ ] **404.** «Такой страницы нет», кнопка «На главную».
- [ ] **Футер:** дисклеймер, «Поддержка: …» с email (и Telegram, если задан), ссылка «Восстановить доступ к
  разбору».
- [ ] **Оферта, политика, согласие.** Открываются, видна жёлтая плашка «Шаблон», плейсхолдеры в
  [квадратных скобках].
- [ ] **/admin** спрашивает пароль. Демо-заказов (`qa@example.ru`) в списках нет.

### §2. Тест (превью — ответы никуда не сохраняются)
- [ ] **№1 — прямой вопрос.** 5 своих вариантов «Определённо да … Определённо нет». «Вопрос 1 из 28», кнопка
  «Назад» неактивна.
- [ ] **Вопрос про жизнь, утечку, ось.** Шкала из 5 подписей, номер раздела сверху («Твоя жизнь в целом» /
  «Из чего складывается твой день» / «Какой ты»).
- [ ] **Клик по ответу.** Вариант подсвечивается, через долю секунды плавно переходит следующий вопрос,
  прогресс-бар растёт. Клавиши 1–5 работают, ← возвращает назад.
- [ ] **№28 — последний.** После ответа появляется экран «Анализируем твои ответы…» с пульсирующим кругом.
- [ ] **«Экран анализа»** отдельной ссылкой выглядит так же.

### §3. Результат: 8 типов × 3 уровня
Открой хотя бы по одному результату каждого типа и все три уровня у одного типа.
- [ ] Шкала дорисовывается, число считает до 25 / 50 / 75; подпись уровня «ниже среднего / средний / высокий».
- [ ] «Ты счастливее N% участников» и пометка «Пока участников мало, сравниваем и с модельным распределением…».
- [ ] Строка про Россию меняется от ответа: низкий уровень — «Скорее нет», средний — «Затрудняюсь», высокий —
  «Определённо да». Ссылка на ВЦИОМ открывается.
- [ ] Тип: название, слоган, описание, три оси с подписями полюсов. У всех 8 типов названия и описания разные.
- [ ] Три утечки с номерами, баллом «N из 100» и текстом. У разных типов набор утечек разный.
- [ ] Ниже по порядку: «Поделиться» с превью карточки → пейволл → «Трекер счастья».

### §4. Гость и шеринг
- [ ] **«Чужой результат».** Сверху «Это результат друга. А какой индекс счастья у тебя?» с кнопкой
  «Пройти тест». Пейволла, шеринга и «Трекера» нет.
- [ ] **«Карточка для сторис».** PNG 1080×1920: индекс, тип, слоган, «А какой у тебя?», адрес сайта.
  Кириллица без квадратиков.
- [ ] **OG-картинки** результата и лендинга, 1200×630.
- [ ] **На результате:**
  - «Скопировать ссылку» меняется на «Скопировано ✓», в буфере ссылка с `utm_source=copy`;
  - «Telegram» и «ВКонтакте» открывают окна шеринга с текстом;
  - «Картинка для сторис» скачивает PNG.

### §5. Пейволл и подписка
- [ ] **Пейволл 490 / 690 / 990 ₽** — открой все три ссылки по очереди. Цена в заголовке, кнопке «Оплатить N ₽»
  и форме одна и та же. Форма открыта: email, чекбокс с оферта- и согласие-ссылками.
- [ ] «Оплатить» неактивна без чекбокса; с неверным email — понятная ошибка.
- [ ] Под формой — «Возврат в течение 14 дней…». Справа размытое превью «Неделя 1. …».
- [ ] Под пунктами пейволла — ссылка «Уже покупал? Восстановить доступ».
- [ ] **«Результат после покупки».** Вместо пейволла — «Твой разбор уже готов» и кнопка «Открыть мой разбор»,
  которая ведёт на отчёт.
- [ ] **«Восстановить доступ».** Введи `qa@example.ru` → «Если с этим email были покупки, мы отправили
  письмо…». В «Почтовом ящике» — письмо «Ссылки на твои разборы» со ссылками на оплаченные демо-заказы. Введи
  несуществующий email — ответ на экране тот же, письма нет.
- [ ] **Модалка «Трекер счастья».**
  - Открывается сразу, email и чекбокс на месте.
  - После отправки — «Спасибо!».
  - Клик по фону закрывает модалку.

### §6. Оплата и отчёт
- [ ] **Мок-касса → «Оплатить успешно».** Страница «Тестовая касса», сумма, замаскированный email,
  пометка «тестовый режим». После клика — «Ждём подтверждения…», затем «Готовим твой разбор…», затем сам
  открывается отчёт. В «Почтовом ящике» — письмо «Твой персональный разбор готов» с контактом поддержки.
- [ ] **Мок-касса → «Отказ».** Экран «Оплата не прошла. Деньги не списаны» и кнопка «Вернуться к результату».
- [ ] **«Ожидание подтверждения оплаты».** Крутится и сам не заканчивается — так и должно быть: вебхук не
  придёт.
- [ ] **«Оплата не прошла»** — тот же экран, что после «Отказа».
- [ ] **Готовый отчёт.** Заголовок с типом, «Скачать PDF» сверху и снизу. Разделы: вступление, индекс, тип
  (сильные стороны и ловушки), три утечки (почему + что делать), советы для типа, план на 30 дней
  (4 недели), «Напоследок», «Трекер счастья» внизу.
- [ ] **PDF** скачивается, кириллица и все разделы на месте.
- [ ] **«Отчёт готовится».** Экран «Готовим твой разбор…»:
  - три шага: «Оплата подтверждена ✓» → «Разбор в очереди / Собираем разбор…» → «Разбор готов»;
  - счётчик «Прошло … с»;
  - «Вкладку можно закрыть — ссылку на разбор пришлём на q***@example.ru»;
  - контакт поддержки.

  Так же выглядит сбой генерации у покупателя (повтор и запасной отчёт идут сами). Через 5 минут без
  «пульса» воркер перезапустит генерацию, и экран сменится на готовый отчёт.
- [ ] На готовом отчёте внизу — «Вопросы, возврат или что-то не так с разбором: …».
- [ ] **Оферта** — вместо `[email для обращений]` стоит SUPPORT_EMAIL (если задан).

### §7. Админка (после своего живого прохода из части 2)
- [ ] Четыре карточки метрик с цветом, «k из n», 95% ДИ, целью и стопом.
- [ ] Воронка от «Визит» до «Оставил email».
- [ ] «По вариантам цены» показывает выручку; «По источникам» показывает твой `utm_source`.
- [ ] «Где отваливаются» — 28 строк с текстами вопросов.
- [ ] Заказы и email; кнопки CSV скачивают файлы, которые открываются в Excel или Numbers без кракозябр.

## Часть 2. Живой путь

Делай в **новом окне инкогнито** (не в QA-режиме), начни с `/?utm_source=manual_qa`.

- [ ] Пройди тест честно до вопроса 10 и обнови страницу — продолжишь с 10-го.
- [ ] Нажми «Назад» дважды и поменяй ответ — тест идёт дальше.
- [ ] Дойди до конца → экран анализа → результат. Сходится ли результат с ощущением?
- [ ] Поделись в Telegram (себе в «Избранное») и во VK (личным сообщением себе).
- [ ] Купи разбор: мок-касса локально, тестовая карта ЮKassa на сервере. Открылся отчёт, на почту (или в лог
  сервера — `[mail:mock]`) пришло письмо со ссылкой.
- [ ] Открой ссылку из письма на телефоне — отчёт открывается без входа.
- [ ] Ещё раз в новом инкогнито купи разбор и **закрой вкладку на странице кассы** после оплаты. Письмо всё
  равно приходит.
- [ ] Ещё раз — **откажись от оплаты**. Видно «Оплата не прошла», результат на месте.
- [ ] Вернись на свой результат — вместо пейволла «Открыть мой разбор».
- [ ] Выйди из инкогнито, открой новое окно → футер → «Восстановить доступ» → свой email → письмо со
  ссылками (локально — `/dev/mailbox`).
- [ ] В `/admin`: твой визит, старт, завершение, шеринг, оплата, источник `manual_qa`; в блоке «Отчёты» —
  время генерации.

## Часть 3. Сервер (один раз после деплоя)

- [ ] Без `SUPPORT_EMAIL` (или с `ADMIN_PASSWORD=change-me`) приложение не стартует, в логе — список проблем.
- [ ] Проверочный алерт: `curl -X POST https://<домен>/api/webhooks/payment -d '{"object":{"id":"test"}}'` →
  в Telegram «вебхук оплаты отклонён».
- [ ] `docker compose logs backup` — строка `backup_done`; в бакете появился файл `app-….db.gz`.
- [ ] Проверочное восстановление (LAUNCH.md «Бэкапы») → `integrity_check: ok`, числа строк правдоподобны.
- [ ] `/pay/mock/…` и `/dev/qa` без пароля → 404.

## Смотреть глазами

### Тексты
- [ ] Нет опечаток, двойных пробелов, «ё» стоит последовательно (лендинг, вопросы, результат, пейволл, отчёт,
  письмо, юр. страницы).
- [ ] Везде на «ты», тон тёплый и спокойный; нет медицинских слов и обещаний «изменить жизнь».
- [ ] Мужской род («счастлив», «согласен») не режет глаз — или фиксируем задачу на нейтральные формулировки.
- [ ] Нигде нет «MBTI», «валидированный», «научно доказанный».

### Вёрстка
Проверь лендинг, вопрос, результат, пейволл, отчёт и админку на ширинах:
- [ ] **1280** — ничего не наезжает, пейволл в две колонки.
- [ ] **1440** — основная ширина: аккуратные поля, крупная типографика.
- [ ] **1920** — контент не растянут, фон заполняет экран.
- [ ] **Мобильный 390 px** (DevTools → iPhone 12/13/14):
  - нет горизонтальной прокрутки;
  - кнопки ответов удобно нажимать пальцем;
  - пейволл и форма помещаются;
  - cookie-баннер не закрывает кнопку ответа.

### Шеринг
- [ ] **Карточка в Telegram** (сторис или пересылка как фото): читается на маленьком экране, индекс и тип видны
  сразу, обрезки нет.
- [ ] **Превью ссылки** в Telegram и VK: заголовок «Мой индекс счастья — N из 100. Тип», OG-картинка с индексом.
  Требует публичного https-адреса: VK и Telegram не видят localhost.
- [ ] Хочется ли самому этим поделиться? Если нет — что мешает?

### Цена и ценность
- [ ] С первого взгляда понятно, **сколько стоит** разбор и **что внутри** (5 пунктов, превью недели 1).
- [ ] Понятно, что это разовая оплата, а не подписка.
- [ ] «Трекер счастья — 390 ₽/мес» не путается с покупкой разбора.

### Нет ли ощущения «гороскопа»
- [ ] Результат опирается на **мои ответы**: в отчёте цитируются мои утверждения и баллы зон, а не общие
  фразы.
- [ ] Отчёты у двух разных типов с разными утечками заметно отличаются (сравни два демо-отчёта или два своих
  прохода).
- [ ] Советы конкретные и маленькие (10–30 минут), а не «поверь в себя».
- [ ] Нет предсказаний и ярлыков судьбы («тебя ждёт…», «ты всегда будешь…»).
- [ ] Формулировка «основан на модели Большой пятёрки» в FAQ звучит честно, без наукообразия.
