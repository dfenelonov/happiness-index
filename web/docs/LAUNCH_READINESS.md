# Готовность к запуску MVP: go / no-go

Состояние на 21.11.2026, ветка `nextjs-mvp`. Статусы:
- **готово** — сделано и проверено тестами или smoke;
- **мок** — работает на заглушке, нужен переход на настоящий сервис;
- **не сделано** — нужна работа агента;
- **нужен я** — действие владельца.

Кто делает: **агент** (код или документы) или **я** (владелец). Блокер — нельзя пускать реальных людей, пока
пункт не закрыт.

Проверочные инструменты:
- `npm test` — 95 юнит-тестов;
- `npm run smoke` — 48 HTTP-проверок всего пути;
- CI (`.github/workflows/ci.yml`) — e2e, скриншоты, Docker;
- `/dev/qa` и [MANUAL_QA.md](MANUAL_QA.md) — ручная проверка.

## Вердикт

**Сейчас запуск на реальных людях — no-go.** Кодовая часть почти готова; блокируют в основном юридические
действия и инфраструктура плюс несколько небольших доработок кода.

Порядок закрытия:

1. **Агент, сразу, без внешних зависимостей** (нужно твоё «да» — это код):
   1. первый зелёный прогон CI: e2e, скриншоты, Docker;
   2. запрет мок-кассы и слабого `ADMIN_PASSWORD` при `NODE_ENV=production`;
   3. ссылка «Твой разбор готов» на странице результата у купившего вместо повторного пейволла;
   4. фоновый догенератор: оплаченные заказы без отчёта → генерация и письмо;
   5. алерт на сбои вебхука и зависшие оплаченные заказы (mock → лог или Telegram);
   6. автоматический бэкап SQLite (сервис в compose);
   7. контакты поддержки в футере и письме.
2. **Ты, параллельно:**
   1. статус (самозанятость или ИП) и договор с ЮKassa;
   2. ответ, как формируется чек для твоего статуса;
   3. уведомление РКН;
   4. юр. тексты с юристом и email поддержки;
   5. вычитка [TEXTS_REVIEW.md](TEXTS_REVIEW.md) и данных ВЦИОМ.
3. **Вместе:** VPS, домен, HTTPS → тестовый магазин ЮKassa и SMTP → тестовый платёж end-to-end (в том числе с
   закрытой вкладкой и отказом) → реальные отчёты YandexGPT.
4. **Ручная проверка** по [MANUAL_QA.md](MANUAL_QA.md) на проде с тестовым магазином.
5. Боевые ключи ЮKassa → очистка тестовых данных в БД → первый трафик с UTM (LAUNCH.md §6).

Не блокируют, но желательно до закупки трафика: шифрование email, Sentry, пометка внутреннего трафика,
возвраты через вебхук, лимиты по IP, удаление данных по запросу.
