# Next.js MVP «Индекс счастья» (`web/`)

Новая основная версия MVP на Next.js + TypeScript. Python-версия на `main` не тронута и заморожена как
референс (см. `CLAUDE.md`).

## Что сделано

- **Флоу:**
  - лендинг;
  - тест из 28 вопросов: по одному на экран, прогресс, «назад», продолжение после перезагрузки
    (localStorage + сервер);
  - экран анализа;
  - бесплатный результат: индекс с анимированной шкалой, перцентиль, тип из 8, три утечки, сравнение с
    ВЦИОМ;
  - шеринг: Telegram, VK, ссылка, PNG 1080×1920;
  - пейволл с A/B-ценой 490 / 690 / 990 ₽ (cookie, `?price=`);
  - фейковая дверь «Трекер счастья»;
  - мок-касса с подписанным вебхуком;
  - отчёт на 1500+ слов и PDF;
  - юр. шаблоны и cookie-баннер;
  - `/admin`: 4 метрики против порогов с ДИ Уилсона, воронка, разбивка по цене и UTM, доходимость по
    вопросам, заказы, email, CSV.
- **Конфиги без кода:**
  - `config/questionnaire.yaml` — вопросы, веса, оси, типы, утечки, пороги, ВЦИОМ;
  - `config/app.yaml` — цены, пейволл, порог перцентиля, пороги метрик;
  - `prompts/report.md` — промпт отчёта.
- **Интеграции через интерфейсы и `.env`:**
  - `PaymentProvider`: mock / yookassa (вебхук перепроверяется запросом к API);
  - LLM: mock / openai / yandexgpt, zod, повтор, fallback;
  - письма: mock / SMTP;
  - Яндекс Метрика — только после согласия на cookie.
- **Перцентиль:** до `percentile.real_results_threshold` (500) настоящих результатов сравнение идёт вместе
  с 500 синтетическими (`is_seed`), на странице есть пометка. С порога синтетика исключается автоматически.
- **Деплой:** Dockerfile, docker-compose, Caddy для HTTPS.
- **Готовность к запуску:**
  - `docs/LAUNCH_READINESS.md` — go/no-go по 7 категориям, вердикт и порядок закрытия блокеров;
  - `/dev/qa` — галерея всех экранов и состояний на демо-данных, исключённых из метрик;
  - `docs/MANUAL_QA.md` — чек-лист ручной проверки.
- **Готовность к проду:**
  - production не стартует с mock-кассой, слабым паролем админки или без `SUPPORT_EMAIL`;
  - контакты поддержки на всех нужных экранах и в письмах;
  - `RECEIPT_MODE` для чека 54-ФЗ;
  - повторная покупка невозможна, есть «Открыть мой разбор» и «Восстановить доступ» по email;
  - фоновая генерация отчёта: 3 × 60 с, запасной отчёт, прогресс, письмо, время генерации в логе и `/admin`;
  - алерты в Telegram;
  - ежедневные бэкапы в S3 с проверяемым восстановлением.
- **CI** `.github/workflows/ci.yml`: проверки и smoke → e2e и скриншоты (артефакты) → Docker build и
  запуск с проверкой главной.
- **Документы:**
  - `web/README.md`, `LAUNCH.md`, `DECISIONS.md` (42 решения), `TODO.md`;
  - `docs/TEXTS_REVIEW.md` — все тексты с пометками «новый/изменён» относительно утверждённой версии;
  - `CLAUDE.md` обновлён: основная версия — `web/`, стек меняется только с согласия владельца.

## Что проверено (локально)

- `npm run lint`, `npm run typecheck`, `npm run build` — без ошибок.
- `npm test` — 140 тестов в 15 файлах:
  - подсчёт и граничные значения;
  - схема конфигов;
  - A/B-цена;
  - прохождение теста;
  - платёжный мок-флоу и ЮKassa на подставном API;
  - отчёт: ≥ 1500 слов на 300 профилях, без ПДн во входе LLM, повтор и fallback;
  - метрики админки, события, лимиты, перцентиль и порог синтетики;
  - демо-данные `/dev/qa`: все типы и уровни, исключение из перцентиля;
  - проверки production, повторная покупка, восстановление доступа, воркер отчётов, алерты, бэкап и
    восстановление.
- `npm run smoke` — 54 проверки: production-обработчик в процессе, весь путь от лендинга до отчёта, PDF,
  админки и CSV; `/dev/qa` закрыта паролем в production, все её 37 страниц открываются, демо-заказов нет
  в админке.
- Smoke в копии проекта только с prod-зависимостями (как в Docker-образе): нашёл и исправил две ошибки
  старта контейнера.
- `npm audit --omit=dev` — 0 уязвимостей.
