# ТЗ: MVP «Индекс счастья»

Версия 1.0 · 30.10.2026

## 1. Цель и критерии успеха

MVP проверяет три ключевых допущения финмодели: люди доходят до конца теста, делятся результатом и платят
за полный отчёт. Плюс измеряем интерес к будущей подписке через фейковую дверь.

| Метрика | Формула (по серверным событиям) | Идём дальше | Стоп / переделка |
|---|---|---|---|
| Дохождение | `test_complete / test_start` | ≥ 60% | < 45% |
| Шеринг | сессии с `share_click` / `test_complete` | ≥ 8% | < 4% |
| Конверсия в покупку | `payment_success / test_complete` (без флага скрининга в знаменателе) | ≥ 2,5% | < 1,2% |
| Интерес к подписке | `sub_fakedoor_click / payment_success` | ≥ 5% | — |
| Вирусный коэффициент | `test_start` с `ref` / `test_complete` | справочно | — |

Размер выборки: для конверсии 2,5% ± 0,5 п.п. нужно ≈ 3 700 прошедших тест. Админ-дашборд показывает
95%-доверительные интервалы (Уилсон), чтобы не принимать решение на шуме.

## 2. Пользовательский путь

```
Лендинг → [согласие] → Тест (≈30 вопросов, по 1 на экран)
        → Бесплатный результат ──→ Поделиться (карточка, ссылка с ref)
                │
                ├─ флаг скрининга? ── да ──→ Блок поддержки (без пейволла)
                │
                └─ нет ──→ Пейволл 490/690/990 ₽ (A/B) → ЮKassa → Страница отчёта
                                                     └─→ Фейковая дверь «Трекер счастья»
```

## 3. Экраны

### 3.1. Лендинг `/`

- Заголовок-хук: «Индекс счастья в России упал до минимума за 15 лет. А какой у тебя?»
- Подзаголовок: «5 минут. Бесплатно. Без регистрации». Цифры о стране берутся из `config/app.yaml`
  (`country_index`), не хардкодятся в шаблоне.
- Кнопка «Узнать свой индекс».
- Блок «Что ты узнаешь»: личный индекс, свой тип, три утечки счастья.
- Блок «На чём основан тест»: признанные психологические шкалы, без названий конкретных методик в
  маркетинговом тексте.
- Футер: оферта, политика ПДн, «не является медицинской услугой».
- SSR, корректные `<title>`, `description`, OG-теги. Время до первого байта < 300 мс.
- Захват UTM-меток и `ref` из URL в сессию (cookie `sid`, httpOnly, 90 дней).

### 3.2. Согласие

Перед первым вопросом — чекбокс согласия на обработку данных со ссылкой на политику. Без отметки тест не
начинается. Факт согласия (время, версия текста) пишется в БД. Отдельный баннер cookie для Метрики:
Метрика грузится только после согласия.

### 3.3. Тест `/test`

- Один вопрос на экран, прогресс-бар, кнопка «назад». HTMX-переходы без перезагрузки страницы.
- Порядок блоков и вопросы — из `config/questionnaire.yaml`. Каждый ответ сохраняется сразу
  (`POST /api/answers`) — так считаем, где люди бросают тест.
- Если человек вернулся по cookie, тест продолжается с места остановки.
- Мобильная версия — основная: кнопки ответов не меньше 44 px, без горизонтального скролла.

### 3.4. Бесплатный результат `/r/{public_id}`

`public_id` — случайная строка 10+ символов (не автоинкремент). Страница доступна по ссылке без cookie.

Показывает:

1. **Личный индекс 0–100** — крупно — и строка «выше, чем у N% участников» (перцентиль среди всех
   завершённых тестов; пока тестов < 500 — строку не показывать).
2. **Ответ на вопрос ВЦИОМ** — «Ты среди 74% россиян, кто считает себя счастливым» или аналог для
   ответа «нет». Доля берётся из `config/app.yaml`. **Нельзя** сравнивать личный индекс 0–100 с индексом
   ВЦИОМ: это разные метрики (индекс ВЦИОМ — разница долей «да» и «нет»).
3. **Тип** — название архетипа, иллюстрация (заглушка), 2–3 предложения описания.
4. **Три утечки счастья** — названия доменов с наименьшими баллами + по одной фразе.
5. **Кнопки «Поделиться»**: VK, Telegram, скопировать ссылку, скачать карточку для сторис.
6. **Пейволл** (п. 3.5) или **блок поддержки** (п. 3.7).

На публичной странице, которую открывает **другой** человек по ссылке, видны только индекс, архетип и кнопка
«Пройди тест сам» (ссылка с `?ref={public_id}`). Утечки и всё остальное — только владельцу (по cookie `sid`).

### 3.5. Пейволл

- Превью отчёта: оглавление и размытый фрагмент первого раздела.
- Цена по A/B-варианту сессии: 490 / 690 / 990 ₽, равные доли, вариант закреплён за сессией (хеш `sid`).
- Поле email (для отправки ссылки на отчёт и чека 54-ФЗ), чекбокс согласия с офертой.
- Кнопка «Получить полный отчёт» → `POST /checkout` → редирект на ЮKassa.
- Гарантия: «Не понравится — вернём деньги в течение 14 дней».

### 3.6. Отчёт `/report/{token}`

- `token` — случайный, 32+ символа; ссылка приходит на email и показывается после оплаты.
- Генерация — после вебхука `payment.succeeded` (фоновая задача). Пока генерируется — экран ожидания с
  автообновлением. Если LLM недоступен 3 попытки подряд — отчёт собирается из шаблонов (fallback) и
  помечается для перегенерации.
- Разделы — по `docs/LLM_REPORT.md`. Кнопка «Скачать PDF».
- Под отчётом — **фейковая дверь**: карточка «Трекер счастья — замеряй индекс каждый месяц и смотри
  динамику. 390 ₽/мес». Кнопка «Хочу» → модалка «Мы запускаем трекер в ближайшие недели. Оставь email —
  пришлём приглашение со скидкой» → `POST /lead`. События `sub_fakedoor_click`, `sub_email_submit`.

### 3.7. Блок поддержки (защитный контур)

Если сработал флаг скрининга (п. 4.5):

- Пейволл **не показывается**. Бесплатный результат показывается полностью.
- Вместо пейволла — спокойный текст: «Похоже, сейчас тебе непросто. Это нормально, и с этим можно
  работать — лучше всего вместе со специалистом». Контакты помощи из `config/app.yaml`
  (`support_contacts`; номера заполняет и проверяет владелец), 112 при угрозе жизни.
- Никаких продаж, апсейлов и маркетинговых писем этому человеку.
- Событие `screening_flag_shown` (без каких-либо ответов), клики по контактам — `support_link_click`.

### 3.8. Юридические страницы

`/offer`, `/privacy`, `/consent`, `/cookies` — тексты-заглушки с пометкой `TODO_LEGAL`, финальные тексты
даёт владелец (см. `docs/LEGAL.md`).

## 4. Подсчёт результатов

Все правила — в `config/questionnaire.yaml`, код — в `app/scoring/`. Ниже — логика.

### 4.1. Личный индекс (SWLS)

5 утверждений, шкала 1–7. Сумма S от 5 до 35. Индекс = `round((S − 5) / 30 × 100)`.

### 4.2. Черты Big Five (BFI-10)

10 утверждений, шкала 1–5, по 2 на черту, одно из пары — обратное (`6 − x`). Балл черты — среднее пары
(1–5), для показа переводится в 0–100: `(m − 1) / 4 × 100`.

### 4.3. Архетип

Определяется по трём чертам: экстраверсия (E), нейротизм (N), открытость опыту (O). Порог «высокий» (строго `>`) —
`threshold` из конфига (на старте 3.0 по шкале 1–5; после 1 000 тестов заменить медианами выборки).
8 комбинаций → 8 архетипов, таблица — в конфиге. Добросовестность и доброжелательность используются только в
платном отчёте.

### 4.4. Утечки счастья

5 доменов (сон и энергия, близкие отношения, работа, деньги, смысл), по 2 собственных утверждения на шкале
1–5. Балл домена — среднее. «Утечки» — три домена с наименьшими баллами; при равенстве — порядок из
конфига (`tie_break_order`).

### 4.5. Скрининг (PHQ-2 + GAD-2)

4 вопроса, шкала 0–3. Флаг = `PHQ-2 ≥ 3` **или** `GAD-2 ≥ 3`. Флаг вычисляется в момент завершения
теста; сырые ответы скрининга **не сохраняются** (держатся в памяти запроса). В БД пишется только
булев флаг, без отметки времени ответов.

### 4.6. Вопрос ВЦИОМ

«В жизни бывает всякое: и хорошее, и плохое. Но если говорить в целом, вы счастливы или нет?»
Варианты: определённо да / скорее да / скорее нет / определённо нет / затрудняюсь ответить.

## 5. Карточка для шеринга

- `GET /r/{public_id}/card.png` — 1080×1920 (сторис), `GET /r/{public_id}/og.png` — 1200×630 (OG).
- На карточке: индекс крупно, архетип, короткий призыв «А какой у тебя?», домен сайта. Без утечек и любых
  данных скрининга.
- Генерация Pillow, кеширование на диске/в S3 по `public_id`.
- Ссылки «Поделиться» ведут на `/r/{public_id}?ref={public_id}` с UTM `utm_source=share&utm_medium={vk|tg|copy}`.

## 6. Данные

```
sessions      id (uuid), sid_hash, created_at, utm_source, utm_medium, utm_campaign, ref_public_id,
              price_variant (490|690|990), consent_at, consent_version
answers       session_id, item_id, value, answered_at          -- кроме блока screening
              PK (session_id, item_id): при «назад» ответ перезаписывается (upsert)
results       session_id, public_id, swls_raw, happiness_index, trait_E/A/C/N/O (1–5),
              archetype_id, domain_scores (json, домен → балл 1–5), leaks (json, 3 id), vciom_answer,
              screening_flag (bool), completed_at
orders        id, session_id, amount_rub, status, yookassa_payment_id (unique), email_encrypted,
              email_hash, created_at, paid_at, refunded_at
reports       order_id (PK — один отчёт на заказ), token, status (pending|ready|fallback|failed),
              content_json, provider, model, tokens_in, tokens_out, created_at
leads         id, email_encrypted, email_hash, source (sub_fakedoor), session_id, consent_at
events        id, session_id, name, props (json), created_at
```

- Email в `orders` и `leads` хранится в зашифрованном виде (`email_encrypted`, Fernet, ключ из `.env`),
  плюс хеш для поиска (`email_hash`).
- `answers.value` — строка: число для числовых шкал, id варианта для вопроса ВЦИОМ.
- Индексы: `events(name, created_at)`, `results(public_id)` (unique), `reports(token)` (unique),
  `orders(email_hash)`, `leads(email_hash)`.

## 8. Нефункциональные требования

- Мобильные устройства — основной сценарий; Lighthouse mobile ≥ 85.
- Хостинг и БД — в РФ (Yandex Cloud / Selectel), см. `docs/LEGAL.md`.
- Логи без ПДн и без ответов теста.
- Rate limit на `/api/answers`, `/checkout`, `/lead` (простая защита от ботов).
- Бэкап БД ежедневно.

## 9. Критерии приёмки MVP

- [ ] Тест проходится с телефона за 5–7 минут, ответы сохраняются по одному.
- [ ] Подсчёт покрыт тестами: граничные значения SWLS (5 → 0, 35 → 100), обратные пункты BFI-10, все 8
      архетипов, равенство утечек, порог скрининга (2 → нет флага, 3 → флаг).
- [ ] С флагом скрининга пейволл не рендерится ни при каких параметрах URL (тест на это есть).
- [ ] Ссылка шеринга приводит гостя на публичную версию результата, `ref` записывается в новую сессию.
- [ ] Тестовый платёж ЮKassa проходит, вебхук идемпотентен (повтор не создаёт второй отчёт).
- [ ] Отчёт генерируется через LLM, при недоступности — fallback-шаблон.
- [ ] Фейковая дверь собирает email с согласием.
- [ ] `/admin` показывает воронку за период с доверительными интервалами и цветом «порог пройден / нет»,
      а также разбивку по A/B-цене и `utm_source`.
- [ ] При `APP_ENV=production` с плейсхолдерами `TODO_LICENSED_TEXT` или `TODO_LEGAL` приложение не стартует.
